# ROS 2 Testing Guide

This document shows how to test the ROS 2 packages in this workspace in two stages:

1. Hardware validation for camera, IMU, and LiDAR only.
2. SLAM + RViz2 validation without mapping or autonomous Nav2 navigation.

The commands below assume you are in the workspace root and have sourced the correct ROS 2 setup for your distro.

**Before doing any ROS 2 operations, make sure to run the command to activate ROS 2**

```
source /opt/ros/jazzy/setup.bash
ros2
```

## 1. Build and source the workspace

Build the workspace after making changes:

```bash
cd slam_ros2_ws
colcon build --symlink-install
source install/setup.bash
```

If you switch ROS distributions, clean the generated folders first:

```bash
rm -rf build install log
colcon build --symlink-install
source install/setup.bash
```

Do not edit `build/` or `install/` manually. They are generated by `colcon`.

## 2. Hardware component tests

These tests are for the sensor packages only. They let you confirm that the device comes up, publishes data, and that the expected topics are visible.

### Camera

Use one of the camera launch files from `ucsd_robocar_sensor2_pkg`:

```bash
ros2 launch ucsd_robocar_sensor2_pkg camera_webcam.launch.py
```

Other camera options in the same package:

```bash
ros2 launch ucsd_robocar_sensor2_pkg camera_intel.launch.py
ros2 launch ucsd_robocar_sensor2_pkg camera_oakd.launch.py
```

Quick checks:

```bash
ros2 topic list | grep camera
ros2 topic echo /camera/color/image_raw --once
ros2 topic echo /camera/image_raw --once
```

If the camera driver publishes compressed images instead of raw images, echo the compressed topic instead:

```bash
ros2 topic echo /camera/image_raw/compressed --once
```

### IMU

The current IMU hardware is the Seeed Technology Co., Ltd. Seeed XIAO nRF52840 Sense. The launch path in this repo is still the same sensor package, but the launch file name is legacy:

Before testing on ROS Jazzy, install the driver dependency once:

```bash
sudo apt install ros-jazzy-tf-transformations
```

If `razor_imu_9dof` is not already in your workspace, clone and build it from source using the same branch the Dockerfile expects.

```bash
ros2 launch ucsd_robocar_sensor2_pkg imu_artemis.launch.py
```

Quick checks:

```bash
ros2 topic list | grep imu
ros2 topic echo /imu --once
```

If the board shows up on a different serial device than the default in [my_razor.yaml](../slam_ros2_ws/src/ucsd_robocar_hub2/ucsd_robocar_sensor2_pkg/config/my_razor.yaml), update the `port` entry before testing. If your IMU driver uses a different topic name, confirm it with `ros2 topic list` and inspect the launch file for the exact remap.

### LiDAR

Pick the LiDAR launch that matches your hardware. Common options in `ucsd_robocar_sensor2_pkg` include:

```bash
ros2 launch ucsd_robocar_sensor2_pkg lidar_ld06.launch.py
ros2 launch ucsd_robocar_sensor2_pkg lidar_livox.launch.py
ros2 launch ucsd_robocar_sensor2_pkg lidar_livox_mid360.launch.py
ros2 launch ucsd_robocar_sensor2_pkg lidar_bpearl.launch.py
ros2 launch ucsd_robocar_sensor2_pkg lidar_rp.launch.py
ros2 launch ucsd_robocar_sensor2_pkg lidar_sicktim.launch.py
```

Quick checks:

```bash
ros2 topic list | grep scan
ros2 topic echo /scan --once
```

For point cloud-based lidars, confirm the published point cloud topic from the driver launch file and use `ros2 topic echo` or `ros2 topic hz` on that topic.

## 3. SLAM and RViz2 test

This stage validates the SLAM package and RViz2 visualization only. It does not require mapping completion or Nav2 autonomous driving.
The current `slam.launch.py` does bring up the Nav2 support nodes used by the package, but for this test you only need to confirm SLAM, TF, scan data, and RViz2 rendering.

Launch the SLAM stack:

```bash
ros2 launch robot_slam slam.launch.py
```

What this starts:

- Robot description and TF tree
- Local EKF
- SLAM Toolbox in online async mode
- Nav2 servers required by the package launch
- RViz2 with the mapping layout

For a focused visual check, verify that these topics are present:

```bash
ros2 topic list | grep -E '/map|/tf|/odom|/scan'
```

You can also inspect the map topic directly:

```bash
ros2 topic echo /map --once
```

### RViz2 checks

When RViz2 opens, confirm:

- The fixed frame is set correctly, usually `map` or `odom` depending on the stage.
- The robot footprint appears in the TF tree.
- Laser scan data is visible.
- The occupancy grid updates while the robot moves.

If RViz2 opens but nothing appears, check:

```bash
ros2 topic hz /scan
ros2 topic hz /tf
ros2 topic hz /map
```
